1.1 Mô Tả & Mục Tiêu Thiết Kế

TLab Monitor SRE là hệ thống giám sát và tự phục hồi hạ tầng tự lưu trữ (self-hosted) thế hệ mới. Được xây dựng trên nền tảng n8n, hệ thống tích hợp sâu mô hình AI (LLM) có khả năng tự động khám phá tài nguyên, suy luận nguyên nhân sự cố và độc lập đưa ra lệnh khắc phục mà không cần mã hóa cứng (hardcode) các thông số mạng.

Bản cập nhật kiến trúc mã nguồn mở (Open-Source) đã loại bỏ hoàn toàn các cấu hình IP tĩnh. Thay vào đó, AI tự động tra cứu, gán dữ liệu động (bơm IP, Token) từ bảng Mapping thông qua môi trường (Environment Variables) để tương tác chính xác với các Docker Hosts, QEMU và LXC trên Proxmox.

1.2 Mục Đích & Vai Trò Của Các Thành Phần Cốt Lõi

Hệ thống được thiết kế để giải quyết bài toán tự động hóa triệt để trong quản trị cụm máy chủ, nhắm đến các đối tượng và công nghệ đặc thù sau:

  • Đối với Docker (Container Management): Khi một container bị treo, ăn cạn RAM (OOM) hoặc bị tắt đột ngột, Prometheus sẽ báo động. TLab Monitor tự động phân giải cấu trúc, gọi trực tiếp vào Docker Socket API để tiến hành khởi động lại (Restart/Start) vùng chứa đó mà không cần kỹ sư gõ lệnh thủ công.
  • Đối với Proxmox VE (PVE - Virtualization): Nhận diện được các máy ảo (QEMU) hoặc LXC bị sập. Hệ thống sẽ tự động ghép nối Proxmox API Token an toàn, định tuyến lệnh gọi REST API đến đúng Node vật lý để đánh thức (Wake up) máy ảo tương ứng.
  • Đối với Trí tuệ Nhân tạo (Agentic AI): Đóng vai trò là "Kỹ sư SRE trực tuyến 24/7". Khi tiếp nhận Metrics, AI sẽ phân tích xem đây là hành vi bình thường (ví dụ: Hệ thống Camera đẩy CPU cao khi có chuyển động) hay là sự cố thực sự. Từ đó AI ra quyết định: Bỏ qua, Tự động sửa, hay Leo thang khẩn cấp (Escalate).
  • Đối với Ntfy (Human-in-the-Loop): Tạo ra một trạm kiểm soát an toàn trên điện thoại. Với các lệnh có rủi ro cao tác động đến hạ tầng lõi, hệ thống sẽ đẩy thông báo Push Notification kèm 2 nút bấm (Approve / Reject). AI chỉ được phép thực thi khi con người xác nhận.

3.1 OC-3 — Agentic Monitor (The Brain)

🧠

OC-3: Agentic Monitor

Dynamic Injection · Zero-Token RAG · AI Reasoning

OC-3 là đỉnh cao của sự tự động hóa. Khi tiếp nhận cảnh báo, AI không xử lý chuỗi "mù". Thay vào đó, Node Live Auto-Discovery Agent sẽ lấy tên dịch vụ và tự động đọc các biến môi trường $env để tra cứu API Proxmox / Docker theo thời gian thực.

Sau khi định vị xong (ví dụ tìm thấy dịch vụ chạy ở 192.168.x.x thuộc loại `container`), nó bơm chính xác thông số vào Payload. Hệ thống RAG Memory sau đó được đánh giá, nếu độ tin cậy của giải pháp cũ vượt mốc 0.90, AI sẽ nhường quyền cho "ký ức" giải quyết sự cố, tiết kiệm 100% token. Nếu không, OpenRouter AI sẽ tiếp quản phân tích.

3.2 OC-1 — Decision Tiering & Guardrail (The Shield)

🛡️

OC-1: Decision & Guardrail

Anti Crash Loop · JSON Integrity

OC-1 chặn đứng hậu quả của việc khởi động lại liên tục. Bằng câu lệnh SQL COUNT(*), nó đếm số lượng cảnh báo trong vòng 10 phút. Nếu một Container hoặc VM sập ≥ 1 lần trong chu kỳ, cầu dao sẽ tự ngắt, phát lệnh CRITICAL qua Ntfy để cầu cứu con người.

Bên cạnh đó, để duy trì toàn vẹn dữ liệu truyền sang hệ thống vận hành, OC-1 bắt buộc phải đóng gói các biến bằng hàm JSON.stringify, chấm dứt hoàn toàn tình trạng lỗi định dạng Object làm sập luồng n8n.

3.3 OC-2 — Multi-Executor & Verification (The Hand)

🤖

OC-2: Multi-Executor & Verification

Smart Sanitization · Dynamic Routing API

Module này đã được loại bỏ hoàn toàn các địa chỉ IP tĩnh. Dựa vào siêu dữ liệu do OC-3 cung cấp, Node thực thi sẽ tự động gọi HTTP Request tới đúng môi trường đích (http://${node_ip}:2375...) một cách chính xác.

Node Clean Input thực hiện làm sạch dữ liệu lần cuối bằng chuỗi Regex replace(/^=/, ''), dọn dẹp các ký tự rác sinh ra trong quá trình luân chuyển dữ liệu trước khi Switch tiến hành rẽ nhánh tác vụ.

3.4 OC-4 — DB Helper & RAG Memory (The Storage)

🗄️

OC-4: DB Helper

Memory Access · Event Processing

Quản lý truy xuất thông qua các đường dẫn Webhook nội bộ. Nó cho phép hệ thống lưu trữ trạng thái tài nguyên (CPU, Memory) vào bảng tlab_events, xuất báo cáo 20 hành động Audit gần nhất và lấy ra các bài học sửa lỗi xuất sắc nhất phục vụ cho AI.

Cơ Chế Bảo Vệ & An Toàn Safety Mechanisms & Guardrails
⚠️
Khắc Phục Lỗi "JSON Render Bug" trong n8n

Lỗi truyền tải JSON dẫn đến định dạng sai Object đã được giải quyết dứt điểm bằng phương pháp Bọc Đầu - Khóa Đuôi:
1. Tại OC-1: Dùng biểu thức JSON.stringify(...) bao bọc lại toàn bộ nội dung gửi đi.
2. Tại OC-2: Dùng Code Node Clean Input thực thi Regex loại bỏ các ký tự vô hình.

📌
Kiểm soát Ảo giác AI (AI Hallucination Guard)

Hệ thống không trao quyền kiểm soát mù quáng cho LLM. Tại phân hệ Parse AI JSON, quy tắc mã hóa cứng được áp dụng: Nếu tài sản được định vị là vùng chứa (container), lệnh xử lý sẽ bị ép tĩnh thành restart, chặn đứng hoàn toàn việc AI sáng tác ra các lệnh phá hoại hệ điều hành.
